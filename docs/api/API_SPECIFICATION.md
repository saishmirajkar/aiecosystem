# API Specification (v1)

The live, exact request/response schemas are generated by FastAPI from the Pydantic models:
* Swagger UI: `http://localhost:8000/api/docs`
* OpenAPI JSON: `http://localhost:8000/api/openapi.json` (a snapshot is exported to
  `docs/api/openapi.json` with `python -m app.cli export-openapi`).

This document defines the conventions every endpoint follows and the endpoint catalogue.

## Conventions

| Topic | Rule |
|---|---|
| Base path | `/api/v1` |
| Auth | Session cookie `above_session` (SPA) or `Authorization: Bearer <token>` |
| CSRF | Cookie-authenticated mutating requests must send `X-Requested-With: above-web` |
| Content | JSON (`application/json`); uploads `multipart/form-data`; CSV exports `text/csv` |
| IDs | UUID strings |
| Decimals | Quantities and money are serialised as **strings** (e.g. `"125.5000"`) to avoid float loss; inputs accept strings or numbers |
| Timestamps | ISO 8601 UTC (`2026-11-18T09:30:00Z`); dates `YYYY-MM-DD` |
| Pagination | `?page=1&page_size=25` (max 200) → `{"items": [...], "total": 0, "page": 1, "page_size": 25}` |
| Sorting | `?sort=name` or `?sort=-created_at`; only whitelisted fields |
| Search | `?q=` free text on documented fields |
| Idempotency | Posting endpoints **require** `Idempotency-Key` (1–100 chars). Replays return the original response with header `Idempotent-Replay: true`; same key + different body → 409 |
| Errors | `{"error": {"code": "string", "message": "human readable", "details": {...}|null, "request_id": "..."}}` |

### Error codes
`validation_error` (422), `authentication_required` (401), `invalid_credentials` (401),
`account_locked` (423), `permission_denied` (403), `not_found` (404), `conflict` (409),
`idempotency_key_required` (400), `idempotency_key_reused` (409), `insufficient_stock` (409),
`business_rule_violation` (409), `invalid_state` (409), `rate_limited` (429),
`setup_already_completed` (409), `internal_error` (500).

## Report identifiers
`current_stock`, `warehouse_inventory`, `stock_movements`, `stock_in`, `stock_out`, `low_stock`,
`overstock`, `inventory_valuation`, `stock_adjustments`, `damaged_stock`, `goods_receipts`,
`product_history` (requires `product_id`), `supplier_purchases`. Filters per report are listed by
`GET /reports`. JSON responses are paginated (`page`, `page_size` ≤ 1000); `?format=csv` streams
all rows (max 50 000) with spreadsheet-formula injection neutralised.

## Example: posting a stock issue
```http
POST /api/v1/inventory/issues
Authorization: Bearer <token>
Idempotency-Key: 6f1c3b0e-6a43-4c55-8f7e-0c4d2f1d9a10
Content-Type: application/json

{"reason": "Issued to machining", "reference_number": "WO-2417",
 "lines": [{"product_id": "…", "warehouse_id": "…", "quantity": "40"}]}
```
`201` → `TransactionOut` with one ledger line per allocated balance (FEFO, then default location).
`409 insufficient_stock` when available stock (on hand − reserved) is short; nothing is posted.
